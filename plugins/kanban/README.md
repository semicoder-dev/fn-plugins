# 看板

`fn-kanban` · `@semicoder/fn-kanban` · 0.1.0，适用于 fn 0.6 / SDK 0.5。

用列表整理进度，用卡片记录任务。交互参考 [Trello 的卡片与列表移动](https://support.atlassian.com/trello/docs/moving-cards-or-lists/)，内容保存在本机，无需账号或模型服务。

## 使用

- 从侧栏进入看板首页，搜索、创建和管理多个看板；每张看板卡片展示列表、卡片和完成数量，右上角菜单可重命名或归档。点击看板进入独立页面，新看板默认有“待办 / 进行中 / 已完成”三列。
- 看板页面顶部保持一行：返回首页、看板名称、搜索、筛选与更多操作。窄窗口的搜索收进“筛选”；标签管理、标签文字显示和当前看板的归档内容收进“更多”。点击侧栏“看板”也回到首页；切换看板时清空搜索和筛选。
- 点“添加卡片”，输入名称后按 Enter 连续添加；Shift+Enter 换行，Esc 收起输入。
- 用鼠标拖动卡片在列表内排序或移动到另一列，拖动列表标题调整顺序。拖起时浮起、目标位置实时占位，周围卡片或列表平滑让位，松手后动画落位并保存。靠近看板左右边缘或长列表上下边缘自动滚动；Esc 或看板外松手取消，回到原位置不保存。系统开启“减少动态效果”时保留占位，关闭倾斜、缩放和过渡动画。触屏保留原生滚动；也可通过列表菜单和卡片详情的“移动与归档”操作。
- 点卡片编辑名称、描述、标签、截止日期、完成状态及检查清单，点击“保存卡片”持久化。卡片被放入“已完成”列表不会自动勾选完成状态，两个概念独立。
- “更多 → 管理标签”或卡片内的“标签”支持创建、重命名、换色和删除。标签在看板内共享，支持同色不同名、30 种配色及无色；有色标签可不命名，无色标签必须有名称且不显示在卡片正面。名称和颜色立即同步到所有关联卡片；删除前确认，删除后也会从归档卡片移除。卡片内勾选标签则在“保存卡片”时生效。
- 点击卡片上的标签、“更多”中的显示选项或按 `;`，切换文字和色条显示，偏好会保存；输入文字及打开弹窗时不触发快捷键。交互参考 [Trello 标签](https://support.atlassian.com/trello/docs/adding-labels-to-cards/)。
- 搜索名称、描述、检查项及标签名称，或按标签筛选；筛选时暂停拖动，避免误改隐藏卡片的顺序。
- 首页“归档看板”恢复看板；看板页面“更多 → 查看归档”仅显示并恢复当前看板的归档列表和卡片。先恢复父看板和列表，再恢复其中的卡片。卡片、列表和看板没有永久删除入口。

## 本地数据与边界

数据位于候选宿主的 `plugins-v1/fn-kanban/kanban-v2.sqlite`，SQLite schema 2、WAL、FULL 同步；每次修改、版本和去重回执在同一事务提交。按用户确认，本候选不兼容或迁移此前固定颜色标签数据；使用新的空数据库，旧 `kanban.sqlite` 不读取、不删除。多个窗口的过期修改会被拒绝，草稿保留，关闭后重新打开卡片或标签编辑器读取最新版。网络重连重试不会重复应用同一请求；回执仅存请求摘要，不重复保存卡片正文。

停用、更新、卸载插件均不删除数据；重装后恢复。备份应先退出宿主，再复制整个 `fn-kanban` 数据目录（包含可能尚存的 WAL 文件）。数据未加密，也不会同步到 iCloud；本插件不读取旧插件数据，不使用浏览器 localStorage 存业务内容。

最多 100 个看板、1,000 个列表、10,000 张卡片；每看板最多 100 个标签，名称最多 80 字符；每卡最多 100 个标签和 100 个检查项，整个文档 8 MiB。归档仍计入容量。首版不提供成员协作、附件、提醒推送、跨看板移动或 Trello 导入；截止日期用于展示与逾期提示。

## 开发与装配

支持 fn 0.6 / SDK 0.5，固定契约和操作命令见仓库根 README。fn 0.5.2 / SDK 0.4 不包含本契约。

- 后端 `src/index.ts` 注入 `host`、`rpc`、`activity`，在 `kanban` 命名空间注册契约；`src/store.ts` 独立持久化，Cordis 销毁时关闭数据库和 API。
- 客户端导出 `./client`，注入原版 slots、默认布局、导航和 `api:kanban`，只贡献 `fn.sidebar.top` / `fn.main`（页面 key `fn-kanban`）。`@semicoder/fn-ui` 提供原版 dsh Button/Input/Menu/Modal 等组件，侧栏使用导航插件公开的 NavigationButton；CSS Modules 与 `--dsw-*` 语义 token 跟随宿主的浅色、深色或系统模式，样式与监听随插件卸载清理。工具栏、列表、详情与空态采用统一的紧凑间距、细线分隔及 dsh 图标；业务标签使用明暗适配的十色、三级浓度。`src/boards.tsx` 提供首页和单行看板顶部，复用 `navigation` 的 `fn-kanban` / `fn-kanban/<boardId>` 子路径；不改变宿主或持久化契约。`src/labels.tsx` 管理共享标签与调色板，卡片通过 UUID 关联标签。
- `fn-ui-navigation/view` 与其局部 CSS 在构建时内联到看板；宿主导航样式改变后，需要刷新本仓对应固定归档并重新打包、更新已安装插件。它不同于运行时共享的 `fn-ui` 控件，来源与逐包摘要见 `vendor/manifest.json`。
- `src/drag.ts` 使用 Pointer Events、局部预览与 Web Animations 驱动拖动，`drag-layout.ts` 计算插入位置与最终命令；没有新增拖动依赖。动画中的位移不参与命中计算；保留拖起时的 revision，拖动期间收到其他窗口修改则取消，松手只提交一次原有 move 命令。所有监听、浮层与动画随页面退出清理。
- 插件 ID 是产品标识，运行包 ID 由市场生成，后端/客户端实例 ID 由 profile 管理。当前包提供单个本机看板服务，不要同时启用两份后端实例注册相同 API 命名空间。
- `fn.iconSvg` 声明固定输出 `dist/icon.svg`，构建脚本复制包内 `src/icon.svg`；市场索引使用 SVG 内容。共享核心和 React 是 peer dependencies，打包不携带它们。

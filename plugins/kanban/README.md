# 看板

`fn-kanban` · `@semicoder/fn-kanban` · 0.1.0 本地候选，尚未发布。

用列表整理进度，用卡片记录任务。交互参考 [Trello 的卡片与列表移动](https://support.atlassian.com/trello/docs/moving-cards-or-lists/)，内容保存在本机，无需账号或模型服务。

## 使用

- 创建多个看板；新看板默认有“待办 / 进行中 / 已完成”三列。可以重命名看板、添加和重命名列表。
- 点“添加卡片”，输入名称后按 Enter 连续添加；Shift+Enter 换行，Esc 收起输入。
- 拖动卡片在列表内排序或移动到另一列；拖动列表标题调整顺序。不使用拖动时，可在列表菜单和卡片详情的“移动与归档”中操作。
- 点卡片编辑名称、描述、六种颜色标签、截止日期、完成状态及检查清单，点击“保存卡片”持久化。卡片被放入“已完成”列表不会自动勾选完成状态，两个概念独立。
- 搜索名称、描述、检查项，或按标签筛选；筛选时暂停拖动，避免误改隐藏卡片的顺序。
- 归档卡片、列表或看板，随后在右上角“归档”中恢复。先恢复父看板和列表，再恢复其中的卡片。当前没有永久删除入口。

## 本地数据与边界

数据位于候选宿主的 `plugins-v1/fn-kanban/kanban.sqlite`，SQLite WAL、FULL 同步；每次修改、版本和去重回执在同一事务提交。多个窗口的过期修改会被拒绝，草稿保留，关闭后重新打开卡片读取最新版。网络重连重试不会重复应用同一请求；回执仅存请求摘要，不重复保存卡片正文。

停用、更新、卸载插件均不删除数据；重装后恢复。备份应先退出宿主，再复制整个 `fn-kanban` 数据目录（包含可能尚存的 WAL 文件）。数据未加密，也不会同步到 iCloud；本插件不读取旧插件数据，不使用浏览器 localStorage 存业务内容。

最多 100 个看板、1,000 个列表、10,000 张卡片；每卡最多 100 个检查项，整个文档 8 MiB。归档仍计入容量。首版不提供成员协作、附件、提醒推送、跨看板移动或 Trello 导入；截止日期用于展示与逾期提示。

## 开发与装配

仅支持全插件化候选宿主，依赖快照和操作命令见仓库根 README。公开 fn 0.5.2、公开 SDK 0.4.0 不包含本契约。

- 后端 `src/index.ts` 注入 `host`、`rpc`、`activity`，在 `kanban` 命名空间注册契约；`src/store.ts` 独立持久化，Cordis 销毁时关闭数据库和 API。
- 客户端导出 `./client`，注入原版 slots、默认布局、导航和 `api:kanban`，只贡献 `fn.sidebar.top` / `fn.main`（页面 key `fn-kanban`）。主样式类以 `fn-kanban` / `kb-` 命名，样式与监听随客户端插件卸载清理。
- 插件 ID 是产品标识，运行包 ID 由市场生成，后端/客户端实例 ID 由 profile 管理。当前包提供单个本机看板服务，不要同时启用两份后端实例注册相同 API 命名空间。
- `fn.iconSvg` 声明固定输出 `dist/icon.svg`，构建脚本复制包内 `src/icon.svg`；市场索引使用 SVG 内容。共享核心和 React 是 peer dependencies，打包不携带它们。
